# Quality Assurance System

moreGeo is not currently certified to ISO 9001. However, we operate a well-defined Quality Assurance System built on established industry best practices in software engineering, open-source development, and project management. Our QA approach is designed to ensure that all deliverables are reliable, maintainable, and meet the customer’s requirements.

## 1. Quality Policy

Our goal is to deliver high-quality software solutions that are robust, transparent, and sustainable. We achieve this by embedding quality at every stage of the software lifecycle and by continuously improving our processes through feedback, peer review, and automated checks.

## 2. Development Workflow and Version Control

All code is maintained in public and private GitHub repositories.

We enforce branch-based workflows (feature branches, pull requests, and protected main branches).

Whenever possible, each change must be peer-reviewed and approved before integration into the main branch.

## 3. Code Review and Peer Collaboration

Every contribution undergoes mandatory code review by at least one other developer or continuous integration tools (e.g., unit tests).

Reviews focus on functionality, security, performance, readability, and compliance with agreed coding standards.

Automated linting and style checks are integrated into the review process to ensure consistency.

## 4. Testing and Continuous Integration

Unit, integration, and system tests are written and maintained alongside the codebase.

A Continuous Integration (CI) system automatically executes the test suite on every change before merging.

Test coverage is monitored, and critical functionality must meet agreed coverage thresholds.

## 5. Release Management

Software releases are versioned and tagged in GitHub.

Release notes document new features, fixes, and known issues.

Deployment pipelines include automated builds, reproducibility checks, and verification steps.

## 6. Documentation and Traceability

Requirements, design decisions, and implementation details are documented in version-controlled repositories.

Issues and tasks are tracked in GitHub Issues/Projects to ensure traceability from requirements to implementation and testing.

Customer deliverables are reviewed against documented requirements before release.

## 7. Security and Reliability

Dependencies are regularly scanned for vulnerabilities.

Security best practices are applied, including code analysis and prompt patching of identified issues.

Backup and recovery procedures are in place for source code and project data.

## 8. Continuous Improvement

Regular retrospectives are conducted to review processes and identify improvements.

Lessons learned are incorporated into updated practices and shared across the team.

## 9. Subcontractor Quality Assurance

Where subcontractors are engaged, we require them to follow the same GitHub-based workflow, including code reviews, testing, and CI pipelines. Their deliverables are integrated only after passing through the same QA gates as in-house work.
